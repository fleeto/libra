### 分类规则

- **known：** 下表 33 个 `hook_event_name`。
- **safely_installable：** exit 0 且 stdout 为空时页面不把它描述成决策；timeout 与非 2 的失败不接管动作。观察者合同禁止非空 stdout、JSON 决策和 exit 2。
- **control_sensitive / HOLD：** `WorktreeCreate`、`WorktreeRemove`、`PreModelSwitch`。本页没有独立的、不接管创建、不接管清理、不阻止切换的观察 API。不得安装。
- **deprecated legacy alias：** 当前 Libra parser 认识、本页事件表没有的 `SessionStop`、`ModelUpdate`、`Compaction`。不是 current installable set。官方对应面是 `Stop`、`PreModelSwitch`/`PostModelSwitch`、`PreCompact`/`PostCompact`。
- **unknown：** 任何其它名字或未知字段。partial，诊断不回显 payload，不另建 taxonomy。缺 `hook_event_name` 或 `session_id` 只登记、不关联。

共同 stdin 字段：`session_id`、`transcript_path`、`cwd`、`hook_event_name`；`prompt_id` 在第一次用户输入前可能没有；`scratchpad_dir` 需要 v2.1.257 且可能没有；`permission_mode` 不是每个 event 都有；`effort.level` 只在工具上下文且模型支持 effort 时出现；`agent_id` / `agent_type` 只在 subagent、teammate 或 `--agent` 时出现。合成 fixture 用这些字段，未知键保留为 partial，不删掉后重序列化冒充 source。

### SessionEnd 上游规则（不是 Codex 3 秒）

页面 SessionEnd 专节（本次抓取）：

- 默认 timeout **1.5 秒**。适用于退出、`/clear`、交互式 `/resume` 切换会话。
- settings 里某个 SessionEnd hook 自己的 `timeout` 会把**总预算**抬到这些 per-hook timeout 的最大值，**上限 60 秒**。没有自己 timeout 的 hook 仍按 1.5 秒取消。plugin 提供的 timeout 不抬预算。
- `CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS` 显式覆盖预算，并成为每个没有自己 timeout 的 hook 的 timeout。v2.1.268 之前该变量只抬总预算，无 timeout 的 hook 仍在 1.5 秒被取消。
- exit 2 只把 stderr 显示给用户，**不能**阻止会话结束。JSON 输出被丢弃。Can block = No。
- `reason`：`clear`、`resume`、`logout`、`prompt_input_exit`、`other`。`bypass_permissions_disabled` 自 v2.1.234 起不再发送，matcher 应丢掉它。未观察真实 payload。

这不是 Codex SessionEnd 的 1 秒/3 秒钳位，也不是把 Libra 现有 10 秒默认 timeout 套到 SessionEnd。CC-03 安装 SessionEnd 时**不得**写 `timeout`，也不得设置 `CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS`，否则会把共享预算抬高并拖延会话退出。观察者必须在 1.5 秒内 exit 0，超时由宿主取消且不阻止结束。

### FileChanged：literal matcher 与 watchPaths

本次页面，不沿用旧的 watch 约束：

- matcher 用 `|` 拆开，每一段是工作目录里的**字面文件名**。`".envrc|.env"` 只监视这两个名字。`^\.env` 会去监视一个真叫 `^\.env` 的文件，不是正则。
- `"*"` 也按字面注册成名为 `*` 的文件，同时匹配每个文件。
- 省略 matcher 匹配每个已被监视的文件，并且**不向监视列表增加任何名字**。
- 监视器只在有人点名之后才启动。点名方式是：FileChanged 组的 matcher 写出至少一个字面文件名，或 SessionStart / CwdChanged / FileChanged 的输出返回 `watchPaths`。
- `watchPaths` 是绝对路径数组，**替换**当前动态监视列表。matcher 配置里的路径始终保留。空数组只清空动态列表。
- stdin 额外字段是 `file_path`（绝对路径）和 `event`（`change` / `add` / `unlink`）。
- 没有决策控制，不能阻止写入。JSON 里宿主读取 `watchPaths` 和 `systemMessage`，丢弃 `continue`。
- 本 event 能写 `CLAUDE_ENV_FILE`，变量保留到下一次 CwdChanged。

CC-03 的 Libra FileChanged 项必须省略 matcher，并且观察者不得输出 `watchPaths`。这样不会注册字面文件，也不会替换用户的动态列表；只有用户或其它 hook 已经建立监视时才被调用。

### 当前 verifier 与 API 内容块（两条不同的形状）

`reasoning.rs` 的 `verify_claude_encrypted_field` 只接受最小合成记录：外层仅 `type=assistant` 与 `message`，`message` 仅 `role=assistant` 与 `content` 数组，`deny_unknown_fields`。`uuid`、`timestamp`、`model`、`usage` 会使它失败。`thinking` 块要字符串 `thinking` 加字符串 `signature`。`redacted_thinking` 块要字符串 `data`。它保存的是 JSON 字符串引号内的 lexical 字节，不把 `\uXXXX` 解码成 UTF-8；重复键拒绝。它的产物是 `EncryptedUnavailable` / `OpaqueEncryptedBytes`。DATA-CAP-20261019 的普通保留不创建这类产物。CC-07 不得把这个函数当作真实 JSONL 阅读器。

### 字节向量（CC-07 必须分开锁定）

| 向量 | 锁定 |
|---|---|
| lexical 与 decoded | 普通导出比较的是解码后的 JSON 字符串，再经过同一凭据扫描。源里的 `\u0043\u0043` 解码后是 `CC`。不得把反斜杠-u 序列当成可读正文，也不得宣称两者字节相同 |
| 重复键 | 拒绝该记录，partial，不取后写覆盖 |
| 空串与缺键 | `thinking:""` 与没有 `thinking` 键分开记。空 `thinking` 加空 `signature` 是空壳，不是 data-obtained |
| 仅 signature 或仅 `data` | 非空则可 data-obtained，readable unavailable |
| 未知块内字段 | 连同 locator 保留，标未解释，不因此删掉已取得的 `thinking` |
| 额外外层键 | 不删键后重序列化冒充 source。CC-05 在原始 source 边界接线；CC-07 只从原字节抽出值 |
