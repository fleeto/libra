## 文档职责

本计划承接 issue #468：为 libra 的 Agent/统计/诊断数据建立**采集与精炼（collection and refinement）**管道，即如何采集会话/诊断/性能/记忆数据，并做去噪、分型、聚合，供后续统计存储（#500）与 episode memory（#451）使用。目标是让数据采集具备可观测、可精炼、可复用的结构，而非散落的日志。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- 数据源：会话（已由 [`plan-20260924.md`](../plan-20260924.md) ACF 协调层与 per-agent 采集计划落库的事实表，如 `agent_session`/checkpoint）、诊断/性能/metrics/记忆事件的采集点登记。
- 精炼：去噪、归一、字段校正、聚合（agg 与 dedup）。
- 输出：面向 #500 统计存储与 #451 episode memory（[`plan-20260926.md`](../plan-20260926.md)）的数据契约；与 `../libra-backend` 的衔接。
- 相关文档与测试。

### 非目标

- 中央化统计存储本身（#500）：本计划只做采集与精炼管道。
- 记忆实现（[`plan-20260926.md`](../plan-20260926.md)，承接 MEM-01/02；原 `plan-20260819` R30 已于 2026-10-07 退役）：本计划的数据采集边界与之衔接，但不重复其设计。
- 第二个 Agent capture 协调层或 hook ingest 面：[`plan-20260924.md`](../plan-20260924.md)（ACF，已收口）已交付 Agent Capture 通用协调层与可插拔储存，[`plan-20260925.md`](../plan-20260925.md)（SCAP，已收口）持有 ingest 决策纯函数 `decide`；本计划的「采集点统一登记」仅指面向统计/记忆数据产品的登记与契约出口，不在 ingest 路径上重复其协调职责，也不新增 hook/parser。

### 成功定义

- 采集点覆盖主要数据源，输出结构化数据；精炼可去噪/归一/聚合。
- 与 #500 统计存储、#451 episode memory 的数据契约一致；端到端可用。
- 提供采集/精炼测试与文档；相关约束登记。
- 各任务卡可独立验收；完成判据全勾选后才标记完成。
