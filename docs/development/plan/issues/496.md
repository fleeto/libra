## 已决议设计决策

实现时若需偏离本节，必须先修改计划并说明原因，不得在代码中静默改语义。

### ADR-CLH-01: 本地路径 clone 复用 `pack_writer::encode_pack_bytes`

- **Status:** Accepted
- **Context:** 复现证据（2026-09-28，本仓 `v0.27.2`）：`libra clone <local-git-path>` 克隆 4 000 提交线性历史死锁于 “Fetching objects”，`timeout 45s` 后仍 0% CPU、目标 `.libra/objects/pack/` 空；`libra clone <local-libra-path>` 克隆 900 提交同样死锁。根因与 #487 ADR-IG-01 相同：`src/internal/protocol/local_client.rs` 内嵌的 `encode_pack_bytes` 是修复前的旧实现——同一任务内先 `for entry in entries { entry_tx.send(..).await }` 喂满容量 1 000 的有界输入通道，再 `while let Some(chunk) = stream_rx.recv().await` 排空容量 1 000 的有界输出通道。对象数 > ~2 000（两通道合计容量 1 000 + 1 000）时，编码器被写满的输出通道阻塞（不再消费输入），喂入循环被写满的输入通道阻塞（不再排空输出）→ 循环等待、全部线程 sleep（`/proc/<pid>/task/*/stat` 状态 `S`，`utime`≈0）。`pack_writer::encode_pack_bytes` 已用「独立 feed 任务 + 主任务排空」修复（见其 `// deadlock` 注释）。
- **Decision:** 删除 `local_client.rs` 的 `encode_pack_bytes`，`encode_entries_to_fetch_response` 改为调用 `crate::internal::pack_writer::encode_pack_bytes`（签名一致：`async fn(Vec<Entry>, HashKind) -> io::Result<Vec<u8>>`，调用点 `.await`），并移除不再使用的 `EntryMeta`/`MetaAttached`/`PackEncoder` 导入。本地 Git 与本地 Libra 其实例（`RepoType::GitRepo` / `RepoType::LibraRepo`）均经 `encode_entries_to_fetch_response`，故同一条修复同时覆盖两种本地源。
- **Alternatives considered:** 在 `local_client.rs` 内原地修补——保留两份实现，违反 GC-02（单一来源），拒绝；`pack_writer` 只为“磁盘写文件”服务、`local_client` 为“sideband 帧”服务——两者 `encode_pack_bytes` 本身就是同一 `PackEncoder` 同一输出，只是下游 sink 不同（帧 vs 写盘），复用字节级编码器不影响各自 sink（ADR-IG-01 同结论）。
- **Consequences:** 本地传输与 `repack`/`pack-objects`/`maintenance` 共用同一编码器，`pack_writer` 后续修复自动覆盖本地传输；本地路径 clone 不再挂起，且 `status --short --branch`/`log --oneline` 可正常使用。
- **Revisit when:** 需要流式/增量编码接口时，在 `pack_writer` 内扩展，而非复制（同 ADR-IG-01）。
